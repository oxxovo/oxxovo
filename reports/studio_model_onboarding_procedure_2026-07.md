## 1. 왜 이미 확장 가능한가 — 데이터 주도 카탈로그

모델은 코드가 아니라 **`model_catalog` 테이블 행(row)** 이다. 신규 모델 추가 = **행 1개 INSERT**,
코드 배포 불필요. UI(2모드·3스텝)는 카탈로그를 읽어 셀렉터를 그리므로 **자동 반영**된다.

| 컬럼 / 메타 | 의미 | 신규 등재 시 |
|---|---|---|
| `id` | 내부 식별자 (예: `nano-banana-pro`) | 부여 |
| `provider` | 벤더 (fal 등) — **표시/집계용, 로직 분기 아님** | 기입 |
| `fal_model_id` | 실제 엔드포인트 (예: `fal-ai/nano-banana-pro/edit`) | 기입 |
| `tier` | `standard` / `draft` (연습장) | 지정 |
| `cost_per_second_usd` | 이미지 행은 **장당 USD**(duration 관례=1) | probe 실측치 |
| `active` | 셀렉터 노출 여부 | 검증 후에만 `true` |
| `metadata.media_type` | `image` / `video` | 지정 |
| `metadata.input_params` | 엔드포인트 고정 파라미터(해상도 등) | 스키마 확인 후 |
| `metadata.ref_images` | 실사용 참조 이미지 수 | 실측 |
| `metadata.prompt_max` | 프롬프트 최대 길이 | 확인 |
| `metadata.has_audio` | (영상) 오디오 유무 | 확인 |
| `metadata.param_whitelist` | 고급 파라미터 화이트리스트 | 실측 파라미터만 |
| `metadata.promotes_to` | (draft) 승격 대상 standard id | 지정 |

**핵심**: 워커/서버/UI 어디에도 벤더명으로 `if` 분기하지 않는다. 입력 파라미터는 **데이터
(`input_params`)** 로 주입 → 새 벤더가 들어와도 코드 변경 0. (오늘 t2i 5종은 참조 필드명이
`reference_image_urls` vs `image_urls`로 달라서, 어댑터도 **메타 데이터로 표현**하고 코드
분기를 만들지 않는 것이 원칙 — 신규 스키마 계열이 생기면 `input_shape` 메타로 흡수.)

## 2. 검증 게이트 (등재 기준) — 우선순위 순

신규 t2i(캐릭터 배우용) 모델은 아래를 **probe 실측**으로 판정한다. 영상(i2v) 모델은 §2b 참조.

| # | 기준 | 합격선 | 불합격 시 |
|---|---|---|---|
| 1 | **캐릭터 일관성** | 같은 배우가 여러 컷서 같은 얼굴 유지(육안) | 제외 — 화장품 CF는 얼굴이 제품 |
| 2 | **실사 얼굴 품질** | photoreal 배우 퀄리티 확보 | 제외 또는 스타일라이즈 전용 라벨 |
| 3 | **실사 얼굴 정책** | AI 실사 얼굴 **거부 안 함** | ★**제외** 또는 `stylized-only` 라벨(실사 경로 차단) |
| 4 | **멀티 참조 활용** | 참조 여러 장으로 정체성 강화(가점) | 감점 — 필수 아님(단일도 통과 가능) |
| 5 | **비용** | 장당 단가 합리적 | 고비용은 정식 티어만/드래프트 제외 판단 |
| 6 | **워터마크** | **가시 워터마크 없음** | ★**제외**(배우 얼굴에 마크 = 치명) — 불가시(SynthID 등)는 허용 |

**★하드 게이트 2개 (#3, #6)**: 실사 얼굴을 거부하거나 **가시 워터마크**를 박는 모델은
실사 배우 경로에서 **부적합**. 스타일라이즈(비실사) 콘텐츠 전용으로만 라벨링해 별도 노출하거나
완전 제외한다. (예: Seedance 영상 = 실사 거부 → i2v 실사 경로 부적합, 스타일라이즈 옵션만.)

### 2b. 영상(i2v) 모델 추가 기준
- 위 #3(정책)·#5(비용)·#6(워터마크)에 더해: **배우 유지**(start_image/elements로 얼굴 일관),
  **오디오 유무**(`has_audio`), **멀티샷 지원**(예: Kling `multi_prompt`), **런타임 파라미터 상호배타** 확인.

## 3. 등재 절차 (단계별)

```
0) 후보 발굴        새 fal 모델/새 벤더 → 스펙·단가·정책·워터마크 1차 조사(문서)
1) probe 비용 산정   장당 단가 × 샷수 → 예상 비용 + 상한 → ★TK 승인 대기
2) probe 실행        공유 베이스(중립 시드) + 동일 프롬프트로 캐릭터 시트 생성
                     · 비용 안전장치: 모델별 첫-샷 게이트 + 누적 상한 자동중단
3) 육안 판정 갤러리   모델별 나란히(스틸+R2 링크) → ★TK 육안 (#1 일관성 최우선)
4) 게이트 체크        §2 표로 PASS/FAIL 기록. 하드게이트(#3·#6) 위반 = 제외/스타일라이즈 라벨
5) 카탈로그 등재      PASS만 model_catalog INSERT (단가/엔드포인트/input_params/ref_images)
                     · 마이그 먼저 Run → 코드/데이터 반영 순서 준수
6) active 전환        UI 배선 + 실브라우저 확인 후 active=true (그 전 셀렉터 무노출)
7) 문서화            probe 결과 + 판정 근거를 reports/에 남김(감사 추적)
```

- **1)의 TK 승인은 필수 게이트** — 유료 probe는 예상 비용 보고 → 승인 후 실행.
- **draft(연습장) 티어**: 실사 시행착오 비용을 낮추려면 저가/저해상도 형제 모델을 draft로 함께 등재
  (`promotes_to`로 정식 승격). draft는 워터마크(DRAFT)·제출불가 규칙 적용.

## 4. 벤더 중립 & 스폰서/파트너 훅

- **중립 원칙**: 카탈로그는 provider를 **표시·집계용**으로만 보유. 특정 회사 우대/종속 로직 금지.
  참가자 선택 UI는 통과 모델을 **평등하게** 나열(정렬은 비용/이름 등 중립 기준).
- **비즈니스 연결**: 향후 AI사 스폰서/파트너가 자사 모델을 올리고 싶을 때, 이 게이트가
  **품질·안전 필터**이자 **공정 편입 기준**이 된다. "게이트 통과 = 등재" 라는 객관 규칙이 있어
  파트너 협상이 자의적이지 않다. (스폰서라도 #3·#6 하드게이트는 예외 없음.)
- **부적합도 자산**: 거부/워터마크로 탈락한 모델도 "왜 부적합인지" 근거를 문서화 → 재도전
  (벤더가 정책/워터마크 개선 시) 시 재-probe 기준으로 재사용.
