> 실행은 건별로 승인받는다 — "승인된 예산 안" 표현은 이후 사용하지 않는다. 2026-09-10
> Gate 1 실행($80, 실측은 그보다 훨씬 낮게 나옴)만 실제로 승인된 것이다.

## 0. 왜 이걸 먼저 하나

Benchmark v1(10→8칸 결함 탐지)은 종료됐다 — "AI가 결함을 보는가"를 앞세웠는데,
정작 이 벤치마크의 실제 용도는 "AI가 참가작 사이의 실력 차이를 가려 순위를 만드는가"다.
결함 탐지가 완벽해도 순위를 못 만들면 채점 시스템 전체가 무의미하다. 그래서 Gate 1은
결함 카테고리 얘기를 전혀 안 하고, 오직 "더 나은 쪽을 더 나은 쪽으로 판정하는가"만 본다.

이미 방증이 하나 있다: `reports/mock_prelim_2026-09-05_analysis.md`(43편 Triple-AI 채점)에서
**verified 점수 폭이 61.83~79.53, 단 17.7점**이었고 43편 중 30편(70%)이 72~78 사이 6점 띠
안에 몰려 있었다. 절대점수 기반 채점은 이미 변별력이 좁다는 신호가 나와 있다 — Gate 1은
이걸 "순위를 실제로 뒤집을 수 있는 명백한 pair"로 통제해서 정면으로 재확인한다.

## 1. Contrast Set 구성 (①)

### 1.1 원칙
- 같은 prompt·같은 subject·같은 length, **생성 모델 등급만 다르게** 해서 후보 pair를 뽑는다.
- ⛔ "구형=하급"으로 미리 라벨링하지 않는다. 최신 모델도 그 프롬프트에서 실패할 수 있고
  구형 모델이 오히려 안정적으로 잘 나올 수 있다 — **생성 후 직접 보고, 명백한 품질 차이가
  확인된 pair만 채택한다.** 확인은 스크리너(TK 또는 지수, 모델 등급을 모른 채 blind로) 1인 이상.
- 애매한 pair(둘 다 괜찮음/둘 다 나쁨/우열 판단 곤란)는 **폐기한다** — 억지로 못 채운다.

### 1.2 생성 모델 등급 후보 (기존 Studio 인프라 재사용, 신규 벤더 조사 불필요)
현재 프로젝트가 이미 실사용 중인 두 등급을 그대로 쓴다(실측 단가 보유, [[project_studio_quality_model_pivot]]):
- **프리미엄 등급**: Kling V3 Pro i2v — 실측 ≈ $0.2565/s
- **표준 등급**: Kling 1.0 standard i2v — 실측 $0.045/s ([[reference-fal-kling-i2v-behavior]])

2단계만으로도 "명백한 우열"이 나올 가능성이 높지만(V3 Pro가 5.7배 비싼 만큼 통상 더 안정적),
**등급 예측 없이** 생성 직후 blind로 직접 봐야 한다 — 오늘 GT19~21 빌드에서 정확히 반대 사례가
나왔다(V3 Pro가 "너무 완벽하게" 나와 의도한 결함이 하나도 안 잡혔던 사고). 즉 등급이 높다고
Gate 1의 "명백히 나음"을 보장하지 않는다는 걸 이미 한 번 실측했다.

### 1.3 프롬프트/subject 풀
같은 prompt로 두 등급을 각각 생성해야 하므로 프롬프트 자체를 새로 설계해야 한다(기존
GT01~21은 완성된 클립을 사후 편집한 것이라 재사용 불가). 제안:
- **15~20개 독립 프롬프트**를 만든다(시즌 실제 참가 주제 풀 — [[project_official_rules]]의
  실제 출제 주제나 이번 시즌 실 신청작 컨셉에서 뽑으면 "실제 제작환경"과 맞아떨어짐).
- subject 다양성 확보: 인물 중심 3~4개, 물체 조작 3~4개, 풍경/배경 중심 3~4개, 빠른 동작
  3~4개, 정적 연출 3~4개 — 실제 참가작 분포와 비슷하게.
- 각 프롬프트당 두 등급 생성 = 15~20 candidate pairs. **목표 20~30 확정 pair**에 못 미치면
  프롬프트를 25~30개까지 늘려 후보를 더 뽑는다(수율 50~70% 가정).

### 1.4 스크리닝 산출물
- 채택된 pair마다: (better, worse, 근거 한 줄, 확신도 상/중) 기록.
- 근거는 **점수가 아니라 서술**("A는 손 형태가 안정적이고 카메라 구도가 의도대로 유지됨,
  B는 후반부 인물 얼굴이 뭉개짐" 식) — 이게 곧 ②의 정답지 재료가 된다.

## 2. 정답지 형식 (②) — Pairwise Only

- 정답은 절대점수가 아니라 **"A가 B보다 위다" 방향 하나**뿐이다.
- 3상태 원칙(v1에서 쓴 POSITIVE/NEGATIVE/UNVERIFIED)을 여기에도 적용: 스크리너가 확신
  못 하면 그 pair는 애초에 채택하지 않는다(정답지에 "애매함"을 남기지 않는다 — v1과 달리
  여기선 세트에 넣는 것 자체가 곧 확정을 뜻한다).
- 정답지 스키마: `{pairId, betterClipId, worseClipId, confidence: 'high'|'medium', humanRationale}`.
  모델별 실제 판정과의 일치 여부만 계산하면 되므로 v1의 `scoreOne`류 계산기보다 훨씬 단순하다.

## 3. 심사관 패널 (③) — 6개 동일 조건

| 모델 | 역할 | 단가(1M 토큰, 기존 실측/공개가) |
|---|---|---|
| Claude Opus 5 | 정규 | in $5.00 / out $25.00 |
| GPT-5.6 Sol | 정규 | in $4.00 / out $20.00 |
| **GPT-6 Astra** | **신규** | **미확인 — 실행 전 조사 필요** |
| Gemini 3.8 Flash | 정규 | in $0.75 / out $3.75 |
| Grok 4.6 | 예비 | in $2.00 / out $6.00 |
| Qwen3.8 Max | 예비 | in $2.00 / out $6.00 |

6개 전부 **동일 프레임 세트, 동일 프롬프트, 동일 pair 순서**로 호출한다(입력 편향 방지 —
어느 쪽을 A/B로 먼저 보여주는지도 pair마다 좌우 뒤집어서 반복 호출해야 위치 편향을 배제할
수 있다, 아래 4.4 참고).

## 4. 평가 기준 (④)

1. **명백한 pair 정확도** — 스크리너가 confidence=high로 표시한 pair에서 각 모델이 better를
   맞히는 비율. 이게 가장 낮은 바(bar)다 — 여기서 못 맞히면 미묘한 구분은 볼 필요도 없다.
2. **중간 pair 구분력** — confidence=medium(차이는 있지만 크지 않은) pair에서의 정확도.
   여기서 성능이 명백한 pair보다 크게 떨어지는 건 정상(기대치), 완전히 랜덤(50%)으로
   무너지는지가 관건.
3. **세 축(Intent/Exec/Originality)이 실제로 작동하는가** — pairwise 판정 시에도 세 축을
   따로 물어(현재 v2.2 구조 재사용), 세 축이 전부 같은 방향으로만 움직이는지(사실상 축이
   1개나 다름없는 것) 아니면 실제로 갈리는 축이 있는지 확인.
4. **반복 안정성** — 같은 pair를 같은 모델에 (a) 좌우 순서를 바꿔서, (b) 완전히 새 호출로
   최소 2회 반복. 방향이 뒤집히면 그 모델은 이 pair에서 "우연히 맞았다"로 카운트(진짜 정답이
   아니다).
5. **evidence-근거 대조** — 모델이 근거로 든 서술(예: "B의 손이 왜곡됨")이 실제 영상의 그
   시점과 맞는지 표본 점검(전수 아님, 오탐/할루시네이션 비율 감지 목적).

## 5. 중단 기준 (⛔)

Gate 1에서 다음 중 하나라도 해당하면 **즉시 중단** — Defect Benchmark도 Anchor도 새로
안 만든다(본부 지시 그대로):
- 명백한 pair(confidence=high) 정확도가 사실상 우연 수준에 근접(예: 6개 모델 평균이
  60%대 이하 — 정확한 컷라인은 본부 판단, 이건 시작점 제안일 뿐).
- evidence가 실제 영상과 자주 안 맞음(근거 자체를 신뢰 못 하면 정확도가 맞아도 무의미).
- 반복 시 방향이 자주 뒤집힘(모델이 일관된 판단 기준이 없다는 뜻).

## 7. 정답 확정 절차 (09-09 2차 갱신, 본부 지시 ②)

⛔ 지수 혼자 "명백한 우열"을 정하지 않는다(순환 논증 위험 — AI가 명백하다고 본 게 사람도
그런지 별개 문제). 확정 절차:
1. **독립 blind 검수 2회** — 후보 pair 목록(마이닝 1차)에 대해, 서로의 판정을 못 보는
   상태에서 두 번째 검수를 별도로 돌린다.
2. **방향이 일치하면 채택.** 두 검수 다 "A가 낫다"거나 다 "B가 낫다"고 하면 그 pair는
   확정.
3. **방향이 갈리면 대표님(TK)이 직접 본다.** 오늘 GT03(이종컷 판정)에서 실제로 blind
   검수 2회가 갈린 전례가 있어 "2회 일치"만으로는 부족하다는 게 이미 실측으로 증명됨 —
   불일치 pair는 자동 폐기가 아니라 TK 최종 판정으로 넘긴다.
4. **애매하면(둘 다 확신 낮음) 그냥 버린다.** Gate 1은 취향 시험이 아니라 "누가 봐도 차이
   나는 것"을 재는 첫 관문 — 애매한 pair를 무리하게 살리지 않는다.
5. 확정된 pair 20~30개를 **대표님이 최종 열람**(Benchmark Release Auditor 역할, 본부 지시)
   — 지수의 역할은 후보를 뽑아 나란히 올리고 자기 의견(A/B 중 어느 쪽이 낫다고 보는지)을
   다는 것까지, 확정 권한은 없다.

## 8. 평가 순서 (09-09 2차 갱신, 본부 지시 ④ — 이 순서 그대로)

1. **Clear-pair directional accuracy** — 확정된 "명백한" pair에서 방향을 맞히는가. 여기서
   못 맞히면 **여기서 바로 중단**(3축 독립성·중간 pair 구분은 다음 단계라 갈 필요도 없음).
2. **A-B reversal consistency** — 좌우 뒤집었을 때도 같은 쪽을 승자로 뽑는가(뒤집혀서
   승자가 바뀌면 그 pair·모델 조합은 상금 대회에 못 쓴다 — 점수가 아니라 승자 방향
   기준으로 잰다).
3. **Repeat consistency** — 같은 순서로 한 번 더 불렀을 때도 같은 승자가 나오는가.
4. **Evidence factual accuracy** — 판정 근거로 든 서술이 실제 영상 내용과 맞는지 표본 대조.
5. (①~④ 통과 후에만) 3축 독립성, 중간 pair 구분력 — 이건 "그다음" 단계.
