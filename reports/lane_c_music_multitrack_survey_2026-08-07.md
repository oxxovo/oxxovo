**배열로 바꾸는 것 자체는 작다. 큰 것은 배열이 아니다.**

1. ★**KAT 골든은 움직이지 않는다** -- 1개짜리 배열이 지금과 **바이트 동일한** 정경

## ① MusicBed를 배열로 바꾸면 무엇이 따라오나

현재 모양 (`lib/cryptobind.ts:227`, `:247`):

```
export type MusicBed = { assetId, source, volume, clipVolume, startMs?, endMs?, fadeInMs?, fadeOutMs? }
export type ComposeEdl = { ..., music?: MusicBed }   // 단일 객체
```

### (a) v1sr 정경 문자열 -- 가장 작다

`edlCanonicalStringV2`는 이미 **APPEND-ONLY 규율**로 쓰여 있다(`:341`):

```
if (edl.music) base.push(`MU:${musicCanonical(edl.music)}`)
```

`musicCanonical`은 필드 순서 고정 8필드를 `:`로 잇는다(`:314`). 복수화는
**`MU:` 섹션 안에서 곡들을 잇는 것**이고, 1개일 때 `join`은 그 자체를 그대로 낸다 --
그래서 **1곡 EDL의 정경과 해시가 안 변한다**. 새 섹션(`MUS:` 등)을 만들 필요가 없다.

- `music?: MusicBed` → `MusicBed | MusicBed[]` (1줄)
- `musicCanonical` 유지 + `musicsCanonical(list)` 신설 (~6 새 줄)
- `MU:` push 1~2줄 + 정규화 헬퍼 `toBeds()` ~3줄
- **1파일 · ~4 바뀜 · ~12 새 줄. 그리고 워커 미러 동일.**

★결정 2건이 여기 있다:
- **결정 1 -- 순서**: 곡들을 `startMs, assetId`로 **정렬**해서 정경을 만드나, 아니면
  배열 순서를 의미 있는 것으로 선언하나. 자막은 정렬(`textsCanonical`), 전환도
  정렬(`afterIndex`)이다. 선례는 정렬 쪽이다.
- **결정 2 -- 구분자**: `MU:` 안의 곡 구분자. 자막은 `|`를 쓴다. `musicCanonical`이
  내부에서 `:`를 쓰므로 `|`는 충돌하지 않는다.

### (b) ★KAT 골든 -- 움직이지 않는다 (실측)

`lib/cryptobind-v2.test.ts:139~141` (그리고 워커 `src/cryptobind-v2.test.ts` 미러):

```
GOLDEN_MUSIC_CANON = 'edl2||clipA:0:5000||T:||G:||MU:lib_elegant_01:library:70:40:0:5000:500:800'
GOLDEN_MUSIC_HASH  = '94ed3ca926c848d849c7ac9debc6a586ec04ed98c7bd7ea4263517bf049d60ca'
```

오늘 앱 코드로 그 픽스처를 직접 계산해 확인했다:

```
edl2||clipA:0:5000||T:||G:||MU:lib_elegant_01:library:70:40:0:5000:500:800
hash 94ed3ca926c848d849c7ac9debc6a586ec04ed98c7bd7ea4263517bf049d60ca   ← 골든과 일치
```

1원소 리스트에 대한 `join`은 그 원소를 그대로 내므로, `MU:` 섹션은 **1곡 EDL에서
정의상 불변**이다. **골든이 움직이는 것은 `musicCanonical`의 필드 순서나 섹션 이름을
건드릴 때뿐이고, 복수화는 그 둘을 건드리지 않는다.** 골든은 그대로 두고 **2곡 골든을
추가**하면 된다(양 레포 각 2상수 + 2테스트, ~20 새 줄).

### (c) ★크로스레포 KAT의 음악 픽스처가 지금 깨진 모양이다 (별건 발견)

### (d) 워커 믹싱 -- 여기가 두 번째로 크다

`oxxovo-studio/src/render.ts:420~457` `mixMusic`은 **곡 1개 전제로 필터 그래프를
직접 문자열로 조립**한다:

```
[0:a]volume=clip[c]; [1:a]<트림·페이드·볼륨·adelay>[m]; [c][m]amix=inputs=2:duration=first:normalize=0[a]
```

복수화 = **베드 체인 N개 + `amix=inputs=N+1`**. ~12줄이 `mixMusic` 안에서 바뀐다.

★여기엔 결정처럼 보이지만 **결정이 아닌 것**이 있다: "곡마다 패스를 한 번씩 돌리면
안 되나". 안 된다 -- `clipVolume`이 패스마다 다시 곱해지고 오디오가 N번 재인코딩된다.
따라서 `mixMusic`은 **리스트 전체를 받아 한 패스**여야 한다. 구조가 답을 강제한다.

부수 변경:

- `renderComposition(..., musicLocalPath?: string)` → 다중 경로 (`:593`) ~2줄
- `worker.ts:766~800` `getRenderMusicPath` = **에셋 1개를 조회·v1m 검증·다운로드**한다.
  곡마다 반복 + 경로 맵 반환 ~15줄. ★검증 규칙(source 일치 / status ready / ai면 본인
  소유)은 **곡마다 그대로 반복**되면 되므로 새 규칙이 없다.
- **워커 2파일 · ~33줄.**

## ④ "구조만 복수를 받게 두고 시즌0은 1개로 제한" -- 가능한가

**가능하다.** 그리고 이게 비용을 가장 크게 자르는 선택이다.

포함: 타입 · 정경(+2곡 골든) · `validateMusicBeds` · `lib/studio.ts` 루프 ·
워커 `mixMusic`/`getRenderMusicPath` · 파리티 · e2e.
제외: **편집기 리스트 UI(~105줄) · 타임라인 음악 레인(선례 225줄).**

→ **11파일 / ~55 바뀜 / ~95 새 줄 / 결정 3건.**

**제한을 어디에 두는가** -- ★DB가 아니다. `lib/music-limits.ts`에 상수
(`MAX_MUSIC_BEDS = 1`)를 두고 `validateMusicBeds`가 읽게 하면 마이그레이션도, SQL도,
`platform_config` 행도 없다(⑥ 준수). 나중에 푸는 건 **그 상수 1줄**이다.
시즌별로 달라야 할 때 `seasons` 컬럼으로 올리는 건 그때의 본체 작업이고, 지금 만들면
"설명할 수 없는 상수"가 하나 더 생긴다.

**이 선택이 사는 것**: 서명·KAT가 영구히 고정되고, 워커가 N곡을 이미 섞을 수 있고,
편집기만 나중에 붙이면 된다. **잃는 것**: 없다 -- 1개 제한 하에서 참가자 화면은 오늘과
글자 하나 다르지 않다.

**결정 3건**(④ 범위):
1. `MU:` 안 곡 **정렬 규칙** (선례 = 정렬)
2. 곡 **구분자** (선례 = `|`)
3. **상수 vs 시즌 컬럼** (권고 = 상수, ⑥ 때문에)

**전면 복수면 +3건**:
4. 곡끼리 **겹침 허용**하나 (겹치면 `amix`가 합산 -- 클리핑은 `normalize=0`이라 사용자
   책임이 된다)
5. **최대 곡 수** (자막·클립처럼 상한이 필요하다)
6. 타임라인 레인에서 곡을 **자를 수 있나**(트림) -- 자막 트랙은 시간만 옮긴다

제니2 확정사항 ③("300곡 카테고리 라벨에 화장품·코스메틱·CF용 금지 -- 라벨만으로 본선
주제가 샌다")을 라벨이 아니라 **이미 있는 UI 문구**에서 발견했다. 라벨을 만들기 전에
같은 누출이 코드에 들어 있다.

`app/studio/compose/ProComposeEditor.tsx`, AI 음악 프롬프트 placeholder:

```
:208  '분위기를 설명하세요 (예: 밝고 경쾌한 일렉트로팝, 화장품 광고). …'
:402  'Describe the mood (e.g. bright upbeat electro-pop for a skincare ad). …'
```

- 성격: 참가자 화면 placeholder. **300곡 라벨과 같은 종류의 누출**이고, 양 언어 모두.
- 도달성: **현재 0.** `musicEnabled`(시즌 컬럼)과 `props.musicAiEnabled` 둘 다 false라
  패널 자체가 렌더되지 않는다. 즉 **잠복 상태**다.
- 켜지는 방식: 시즌 컬럼 UPDATE = **SQL 한 줄, 배포 없음.** 릴리스 절차가 잡을 지점이
  없다 -- `season0_to_season1_transition.md`의 P1과 똑같은 모양이다.
- 고치는 비용: **2줄**(KO/EN 각 1). 중립어로 바꾸면 된다.

★고치지 않고 올린다. 문구는 내 소관이 아니고, "무엇으로 바꾸나"가 곧 중립 어휘 결정
(⑥C 대기 중인 그 결정)이기 때문이다. **다만 300곡 라벨 규칙을 정할 때 이 2줄을 같은
결정에 포함시켜야 한다** -- 라벨만 중립어로 만들고 이 placeholder를 두면 누출은 그대로다.
