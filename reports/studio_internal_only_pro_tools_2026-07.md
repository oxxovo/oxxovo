# "외부 소스 0 + 프로 완성도" 기술 실현성 (2026-07-10, 지수2)

TK 방향 확정: 외부 소스 없이 OXXOVO 자체 AI 영상만으로 **A(순수성)+B(프로 완성도)**.
모든 소스가 내부 AI 생성 → provenance 유지하며 프로급. 코드 실측 판단.

## ★대전제 발견 — 체인이 이미 이 제약을 강제한다

CryptoBind 체인(`lib/cryptobind.ts` + 워커 미러) 실측:
- per-clip: 생성 시 `pid|tid|jobId|생성시각|모델|길이` 서명 + 콘텐츠 해시(출력 바이트
  sha256) 서명.
- compose: `source_bundle = sha256(소스 클립들의 생성시각 서명 정렬결합)`. **합성본은
  유효 플랫폼 서명 자산으로만 구성 가능.** 외부 업로드는 생성시각 서명이 없어 **원천적
  체인 진입 불가.**

→ "외부 소스 0"은 새로 붙일 제약이 아니라 **체인의 기존 불변식.** 이걸 깨는 유일한 것이
외부 업로드였다. 업로드 금지 + 내부 생성 강제 → provenance는 구조적으로 유지된다.

## Q1. t2i → i2v (내부 생성 이미지만)

**가용성 (fal 실측)**: 완전 가능.
- t2i: `flux-2` / `flux-pulid` / `flux-subject` / **`ideogram/character`(인물 일관 특화)**.
  flux/dev는 우리 워커에서 이미 검증됨(REF30 probe).
- i2v: **Kling v3 pro i2v**(`start_image_url`+`end_image_url`+`multi_prompt`) / **PixVerse
  i2v**(`camera_movement` enum) / Seedance·Hailuo i2v.
- ★조합 = flux/ideogram로 캐릭터 키프레임 1장 생성 → i2v로 애니메이트 + 카메라 제어.

**체인 진입 = 확장 필요하나 소규모**:
- 생성 이미지를 플랫폼 자산으로 서명(v1i canonical, 기존과 동일 HMAC/secret).
- i2v job의 바인딩에 **부모 이미지 서명을 포함**(compose source_bundle과 동일 원리).
- 결과 체인: t2i(서명) → i2v(서명, 이미지서명 참조) → compose(서명, i2v서명 번들).
  전부 플랫폼 생성으로 추적. **크립토 변경은 작다**(양 레포 byte-for-byte 미러).

**무결성 충돌 해결? → YES.** 외부 업로드가 없고 레퍼런스가 플랫폼 생성 서명 자산이므로
과거 "업로드=미프로비넌스" 문제가 사라진다.

**발사 전 가능? → 경계선(borderline).** 크립토는 작지만 **전체 파이프라인**(이미지 생성
job 타입 + 2단계 UI + 이미지 모더레이션 + 크레딧 가격 + i2v 워커 배선 + 신규 컬럼
media_type/input_asset_id/input_asset_signature)은 **중~큼.** 최소 스코프(t2i 1모델·i2v
1모델·2단계 UI)면 발사 전 가능, 아니면 발사 직후 fast-follow 권장.

**★보너스**: 이게 데모2 캐릭터 일관성 실패의 해법. 캐릭터 1장 생성 → 여러 i2v 샷에
같은 시작프레임 → 인물 일관. **A(순수)와 B(완성도=일관성+카메라제어)를 동시에 준다.**

## Q2. "내부 생성만" 원칙 도구 전체 + provenance + 발사

| 도구 | provenance | 규모 | 발사 |
|---|---|---|---|
| **카메라 디렉팅**(프롬프트/프리셋/Director) | ✅ (파라미터만) | 소~중 | **전** |
| **i2v(내부 생성 이미지)** | ✅ (t2i 서명→i2v가 이미지서명 바인딩) | 중~큼 | 경계선/직후 |
| **AI 네이티브 편집**(생성요소 재변형+재서명: 업스케일/리스타일/확장/AI전환) | ✅ (각 변형=플랫폼 생성, 부모서명 참조) | 큼 | **후** |
| **정밀 큐레이션**(많이 뽑고 고르기) | ✅ (이미 존재) | 소 | **전**(존재) |

원리 공통: **모든 도구가 "플랫폼 생성+서명"이면 provenance 유지.** 외부 LUT/음악/AE 등
사람 손 외부 도구만 배제하면 됨. seed는 3모델 미지원(변주 재생성 불가).

## Q3. 발사 전 최소 A+B 세트 (재확정)

- **확정 전(모두 발사전 가능)**: 카메라 디렉팅 + 카탈로그 확장(Hailuo/Director+Sora제거)
  + 큐레이션(존재).
- **A+B를 규정하는 추가 = i2v(내부 이미지).** "프로 완성도"의 본체(캐릭터 일관+카메라).
  중~큼이라 **최소 스코프로 발사 전 포함**하거나 **직후 fast-follow.** 솔직히 이게 유일한
  스코프 리스크 항목. → TK가 "발사 전 i2v까지 vs 카메라까지"를 정하는 결정.
- **최소선**: 카메라 디렉팅만으로도 "프롬프트 원툴 탈출 + 순수성"은 성립(A + B의 상당부분).
  i2v는 B의 완성도를 한 단계 올리는 증분.

## Q4. compose "AI 네이티브 편집" — provenance 유지하며 가능?

**아키텍처 경계선**:
- trim/cut/sequence = **신규 픽셀 0**(위치 메타데이터, 소스 바이트 보존 → 소스 서명이
  이어붙임을 그대로 검증). 현재 compose가 여기.
- AI 전환/리스타일/매치컷 = **신규 픽셀 발생** → 그 픽셀은 **플랫폼 생성 서명 자산**이어야
  함. 각 편집 연산을 플랫폼 생성으로 만들고 부모 클립 서명을 번들에 바인딩하면 체인 유지.
  (최종본 바이트 해시 v1sc는 이미 신규픽셀을 덮지만, "플랫폼 생성"임을 증명하려면 파생
  자산 서명이 번들에 들어가야 함.)

**결론**: **provenance 유지하며 가능. YES.** 단 모든 편집 연산이 내부 AI 생성일 때만
(외부 도구·업로드 배제). 이는 TK 새 방향(디렉팅/편집 실력 보상)과 철학적으로 정합.

**단 솔직히**: 현 compose "why" 패널은 명시적으로 "전환/효과 금지"라 **재메시징 + 큰 빌드.**
= **발사 후.** 발사 전엔 compose는 몽타주(선택/순서/pacing) 유지, 창작 실력은 생성 단계
(카메라/i2v/반복)에 실어 A+B 성립.

## 발사 범위 권고 (실측)
- **발사 전(확정)**: ①카탈로그 확장 ②카메라/모션 컨트롤(프리셋+고급) ③프롬프트 가이드.
- **발사 전(TK 결정 항목)**: ④i2v(내부 생성 이미지) — B 완성도 본체, 최소 스코프면 가능.
  이걸 넣으면 캐릭터 일관+카메라제어로 "프로급"에 실질 도달. 안 넣으면 직후 fast-follow.
- **발사 후**: AI 네이티브 편집(compose 확장) + Motion Control + 파생자산 서명 일반화.
- 크립토 체인은 이 전부를 **동일 원리**로 수용(플랫폼 생성+서명 바인딩). 양 레포 미러 유지.
