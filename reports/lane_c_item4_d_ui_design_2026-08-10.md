# D — 편집기 UI 설계 (③, 설계만 — 미구현) — 2026-08-10

★설계. 코드 0줄. 배선①②(GL 프리뷰/워커 render.ts) 완료·파리티 실측 완료가
전제. 대상: 효과 4개(exposure/contrast/saturation/vignette, 결정①(a)) + 자막
불투명도(결정①(c)). 위치·스케일은 범위 밖(제니2 결정), 이징 없음(결정②).

## 결론 먼저

기존 슬라이더 그리드(`ProComposeEditor.tsx:1664-1691`)에 **필드별 토글** 하나
붙이는 모양으로 간다 — 세그먼트 전체를 "키프레임 모드"로 바꾸는 전역 스위치가
아니라, exposure만 키프레임하고 contrast는 그대로 정적일 수 있어야 정경 계층
(`kf=` 필드별 옵션 맵)과 1:1로 대응한다. 자막 불투명도는 기존 fadeIn/fadeOut
슬라이더가 없어서(현재 텍스트 레이어에 "opacity" 필드 자체가 없다, 확인함 —
있는 건 startMs/endMs/fadeInMs/fadeOutMs뿐) **새 섹션**이 필요하고,
fadeIn/fadeOut과 상호배타로 둔다(아래).

## 1. 진입점 — 필드별 토글

각 슬라이더 라벨 줄(`spec.label` 옆, `1670`)에 작은 다이아몬드 아이콘 버튼을
추가. OFF(기본) = 지금 그대로 단일 슬라이더. ON = 슬라이더가 **미니 키프레임
트랙**으로 바뀐다(아래 2). 토글 ON 즉시 현재 정적값으로 2점을 자동 생성
(start@val, end@val) — 진입 순간 값이 튀지 않게. **2점 미만으로 못 내려간다**
(마지막 점 삭제 시도 = 토글 자체가 OFF로 돌아가고 그 남은 점의 값이 새 정적
값이 됨) — 정경 계층이 이미 `!track.points.length`를 "없음"으로 취급하므로,
1점짜리 "키프레임"이라는 애매한 상태를 UI 차원에서 아예 안 만든다.

## 2. 미니 키프레임 트랙

세그먼트 폭(`startMs..endMs`, 세그먼트-상대 0..span)에 대응하는 좁은 가로
바(슬라이더 자리를 대체, 기존 slider 높이 유지 — 레이아웃 안 늘어남).
- 점 = 작은 원, x=atMs/span, y=value를 slider의 min..max 범위에 매핑.
- 트랙 클릭(빈 자리) = 그 x 위치(현재 재생헤드 스냅 옵션)에 현재 interpolated
  값으로 새 점 추가.
- 점 드래그 = x(시간)·y(값) 동시 이동, x는 [0,span]·인접 점 사이로 클램프
  (교차 방지 — 순서가 곧 canonical 정렬 키라 교차해도 깨지진 않지만 UX상
  혼란).
- 점 더블클릭 = 삭제(단 2점 미만 방지, 위 1항).
- 선택된 점 옆에 숫자 입력 하나(값 정밀 입력, 기존 슬라이더 옆 `val` 에코와
  같은 자리) — 드래그만으론 정밀值 못 낸다.
- 재생헤드 마커(세로선) = 프리뷰 스크럽과 동기화된 현재 segRelMs 위치 표시만,
  드래그 대상 아님.

## 3. 자막 불투명도(①(c)) — 새 섹션, fadeIn/fadeOut과 상호배타

현재 fadeIn/fadeOut(`1907-1920`)은 값이 아니라 **지속시간**이고, opacity
0→1→0의 내장 2단 선형 램프를 암묵적으로 만든다 — `opacityKeyframes`는 이걸
**일반화**한 것(임의 점 개수)이지 별개 개념이 아니다. 그래서:
- 기본 상태 = 지금 그대로 fadeIn/fadeOut 슬라이더만 보임(단순 경로 유지).
- "고급" 토글 하나 = fadeIn/fadeOut 슬라이더를 **동일한 시각효과의 4점
  opacityKeyframes로 변환**해서 미니 트랙으로 스왑
  (0:0, fadeInMs:1, span-fadeOutMs:1, span:0 — 지금 값 그대로 시드, 안 튐).
  이 시점부터 fadeIn/fadeOut 필드는 정경에서 무시(2에서 만든 트랙만 신호).
  "고급" 끄기 = 트랙 삭제하고 fadeIn/fadeOut 슬라이더로 복귀(값은 트랙의
  처음 두 점 간격에서 역산 시도, 실패하면 0으로 — 손실 변환이라 되돌리기
  버튼 근처에 경고 문구 필요).

## 4. 데이터 흐름

`setSegFx`(`1136`)와 나란히 `setSegKeyframe(uid, key, track)`을 추가, 커밋
undo 스택은 기존 `commit()` 패턴 재사용(다른 슬라이더들과 동일). `track:
undefined`로 호출하면 그 필드의 키프레임 제거(정적값 복귀) — OFF 토글이 이걸
호출.

## 밖에 둔 것

- 이징 없음(결정②) → 트랙 UI에 곡선 선택 드롭다운 없음, 점 사이는 항상 직선.
- 위치·스케일 없음(결정①(a)) → 이 트랙 컴포넌트는 4개 효과 키 + opacity에만
  붙는다, 텍스트 x/y나 클립 트랜스폼에는 안 붙는다.
- 다중 선택(여러 점 동시 드래그) 없음 — 점 하나씩만.

## 관문

새 UI 자체는 파리티 대상이 아니다(값은 그대로 `lib/edl-keyframes.ts`를 거쳐
기존 파리티 배선①②로 흐른다) — UI 관문은 접근성/undo-redo 정합성뿐, 새 harness
불필요.
