# OXXOVO Studio -- 인-플랫폼 짜깁기(멀티클립 합성) 실현성 견적

작성: 2026-06-11 (지수2). **실제 코드/스키마 기준, 추측 없음.** 특허 해석은 디앤특허 영역 -- 본 문서는 무결성 메커니즘만 기술.

## 0. 비전 정의
참가자가 OXXOVO 안에서 클립 N개 생성 → 플랫폼 내장 편집기로 순서/이어붙이기 → 완성본 1개 렌더 → 제출. 외부 업로드 없음. 채점 대상 = 완성본. CryptoBind = 완성본(소스 클립 서명 묶음 + 최종 해시)까지 확장.

## 1. 현재 구조 실측 (변경 영향의 출발점)
- 제출(`lib/studio.ts` submitGeneration): **단일 generation_jobs 1개**의 `video_url`을 `genesis_applications`(예선 `free_entry_url` / 본선 `main_round_video_url`)에 기록 + 잡 `ready→submitted` 락. 제출 단위 = 잡 1개.
- CryptoBind(`lib/cryptobind.ts` + 워커 미러): 2단계. 생성서명 `v1|pid|tid|jobId|generatedAt|model|duration`, 콘텐츠서명 `v1c|jobId|tid|contentHash`. **전부 잡 1개 단위.**
- 워커(`oxxovo-studio/src/worker.ts`+`fal.ts`+`r2.ts`): fal 호출→다운로드→R2 PUT만. **ffmpeg/합성 코드 없음.** 6-state(queued→generating→uploading→ready→submitted→failed).
- 채점(`oxxovo-scoring`, batch.ts:166): 제출 1건당 `video_url, creator_statement, creator_name, id` **4컬럼만** 읽음. 영상 URL 다운→프레임 ~20장 균등샘플→Triple-AI. **CryptoBind/prompt/model/clip 메타 미참조.** Intent(25%)=단일 statement 1개 대조. Execution(45%)은 "continuity/artifact" 평가 → 의도적 컷을 아티팩트로 오인할 소지.

## 2. 필요한 빌드 + 공수 (각 항목 실제 코드 표면 기준, 단일 개발자 dev-day)

### A. 인-플랫폼 편집/시퀀싱 UI -- 신규, 최대 비중
현 `app/studio/page.tsx`(~730줄, 단일 클라이언트 컴포넌트: 생성/목록/제출)에 **시퀀싱 surface 신설**: ready 클립 멀티선택 + 순서지정(배열 state + up/down 또는 드래그) + 미리보기 + "렌더" 액션(신규 server action) + 렌더잡 폴링 UI(기존 잡 폴링 패턴 재사용).
- 트림 없음(순서+이어붙이기만): **3~4 dev-day**
- 타임라인 스크럽 + 클립별 트림: **+3~5 dev-day**

### B. 완성본 렌더(합성) 파이프라인 -- 신규, 인프라 의존
워커에 **렌더 잡 타입 신설**: `render_jobs` 폴링 → 소스 클립 N개 R2 다운 → **ffmpeg concat** → 해시 → 바인딩 → R2 업로드 → ready.
- **ffmpeg를 Railway 워커에 추가**(nixpacks로 가능). 동일 티어(같은 코덱/해상도/fps) 클립이면 concat demuxer로 빠르게(무재인코딩); 혼합 티어/비율이면 **재인코딩(concat filter)** 필요 → 시간·CPU·화질손실. 클립별 네이티브 오디오 이어붙이면 컷 지점 오디오 단절 처리 필요.
- 신규 상태머신 + 실패/환불 + dev 가드. **4~6 dev-day**(인프라+해피패스+재인코딩 폴백+테스트).

### C. CryptoBind 완성본 확장 -- 신규, 양 레포 lockstep
신규 3단계 바인딩: 캐노니컬 예) `v1s|pid|tid|finalId|<정렬된 소스jobId들>|finalContentHash`. 워커가 렌더 시 서명, 메인앱 제출 검증에서 **(a) 각 소스 클립의 기존 CryptoBind 재검증**(pid/tid 일치·서명 유효) **+ (b) 완성본 묶음서명 + 최종 콘텐츠 해시** 검증. `render_jobs`에 바인딩 컬럼. 양 레포 byte-match + 테스트. **2~4 dev-day.**

### D. 채점 대상 변경 -- 소규모
완성본도 "R2 mp4 1개"라 **채점 ingest 형태는 오늘과 동일**(URL 1개). 제출이 완성본 URL을 같은 컬럼에 쓰면 채점은 거의 무변경. 옵션: Execution 프롬프트에 "의도적 컷 허용" 문구 + clip 메타(JSONB) 전달로 Integrity 정확도 향상. **1~2 dev-day**(미세조정), 최소 0.

### E. 규칙/검증/스키마 -- 소규모
길이 규칙 의미 변경(현 "15초 단일 고정" → "클립당 15초 × N → 완성본 M초"): 완성본 min/max 길이, 클립 수 min/max, 라운드 캡 의미(생성=원재료 vs 제출=렌더 1개) 재정의 + platform_config + UI 카피. 신규 `render_jobs` 테이블. **1~2 dev-day.**

### F. 교차 E2E + 엣지 -- 필수
양 레포 E2E, 콘텐츠바인딩 지문 일치, concat 엣지(코덱/오디오/순서변조), 렌더 dev-mode 가드. **2~3 dev-day.**

**합계: 약 13~22 dev-day(코어 13~18 + 버퍼).**

## 5. 핵심 통찰 (길이 비전과의 연결)
짜깁기는 **"fal이 단일 20초 초과 불가" 문제를 합성으로 우회하는 정공법**이다. 15초 Kling 클립 2~4개를 이어붙이면 **30~60초 완성본**이 되어, 원래 비전(15~30초+)을 모델 한계 없이 달성. 즉 단일-15초 결정과 짜깁기는 배타가 아니라 **로드맵 단계**: 시즌0=단일 15초(6/30), 짜깁기=라이브 시즌 fast-follow.
