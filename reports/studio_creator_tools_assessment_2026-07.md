# 참가자 도구 강화 실무 판단 (2026-07-10, 지수2)

TK 전략 통찰: "프롬프트만으로는 프롬프트 잘 쓰는 사람이 이긴다. 참가자가 스튜디오에서
더 좋게 다듬어 올려야 진짜 실력이 보인다." → 발사(7/25) 전 어디까지 도구를 넣을지
판단 근거. 코드 실측 기반.

## 현재 스택 실측 (개발 규모 산정의 토대)

- **생성 UI** (`app/studio/page.tsx`): 참가자 입력 = **모델 선택(select) + 길이(slider)
  + 프롬프트(textarea)** 3개. `createGenerationAction({ modelId, prompt, durationSeconds })`.
- **저장/워커** (`lib/studio.ts createGeneration` → `generation_jobs` → 워커 `processJob`):
  fal 입력 = `job.prompt` + `duration` + **`model.metadata.input_params`**(카탈로그 per-model,
  resolution/aspect 등). **per-generation 사용자 파라미터는 prompt/duration/model 뿐** —
  카메라/negative/cfg 등을 넣으려면 job에 새 컬럼 필요.
  - ★워커는 이미 `extraInput`을 spread → **job에 `user_params jsonb` 추가하면 워커는
    ~5줄로 병합 가능**(구조는 이미 열려 있음).
- **compose** (`ComposeEditor.tsx`): **sequence(재정렬)+trim+cut 전용.** 전환/VFX/색보정/
  자막/외부오디오 **의도적 배제** + "why" 패널(프로 편집자 불공정 우위 방지, "겨루는 건
  AI 생성물"). 하드컷 고정 = Genesis Rule.

## Q2. "진짜 실력"이 드러나는 최소 도구 세트

실력 격차가 나오는 축 (오늘 실측이 증명한 것 = 카메라/모션 디렉팅):
1. **프롬프트 크래프트** — 이미 있음. 가이드/예시만 보강.
2. **★카메라/모션 컨트롤** — 오늘 테스트가 증명한 최대 레버("디렉팅" 실력). = 유일한
   **신규 필수 추가**. Director 대괄호(작음) 또는 negative+camera 프리셋(중간 경량).
3. **모델 선택** — 이미 있음. 샷에 맞는 모델 고르는 안목.
4. **반복+큐레이션** — 이미 있음. 많이 뽑아 최선 고르고 pacing으로 잇기.

→ **최소 세트 = 카메라/모션 컨트롤 1개만 신규.** 나머지 3축은 이미 스택에 존재.
가장 고레버리지 + 발사 전 실현 가능.

## Q3. 진입장벽 균형 (초보·고수 동시 커버)

1. **점진적 노출(progressive disclosure)**: 기본 모드 = 프롬프트+모델+길이(오늘 그대로).
   고급(접힘) = 카메라/negative/cfg. 초보는 기본만으로 완결.
2. **★프리셋 칩 / "디렉터 레시피"**: 원클릭 "빠른 추격" "드라마틱 슬로우 푸시" "휩팬 리빌"
   이 프로 카메라 언어를 프롬프트에 주입. **초보는 한 번 클릭으로 80%, 고수는 수작업으로
   100%.** 프리셋이 곧 교재 → 초보가 배우며 고수로. 두 층 동시 커버의 핵심 장치.
3. **좋은 기본값**: 우리 negative_prompt + 합리적 카메라 기본 → 고급 무시해도 준수한 결과.
4. **인라인 예시**: 오늘 잘 나온 프롬프트를 템플릿으로 제공.

## Q4. compose에 "편집 실력"을 더하려면 — ★정직한 긴장

**현 compose는 편집 실력이 드러나면 안 되도록 의도 설계됨** (전환/VFX/색/자막/오디오
배제, "프로 편집자 불공정 우위 방지"). TK 통찰과 정면 일부 충돌.

**철학 안에서 실력이 드러나는 편집 = 몽타주**: 샷 선택·순서·trim pacing·하드컷 타이밍.
이건 진짜 편집 크래프트(쿨레쇼프/리듬)이고 이미 허용됨. 가시성 강화 방법(무결성 유지):
- 프레임 단위 trim 정밀도, 비트/리듬 가이드, "cut on action" 정렬 보조, pacing 피드백.

**절대 넣으면 안 되는 것**(넣으면 "편집 대회"로 변질 = 무결성 붕괴): 전환효과, 색보정,
외부 오디오, 텍스트/자막, 속도 램프.

**★전략적 화해 (핵심 권고)**: TK가 원하는 "더 큰 창작 실력 노출"은 **compose가 아니라
생성 단계**(카메라/모델/반복)에 넣는다. compose는 몽타주 전용 유지. 그러면 "겨루는 건
AI 생성물"이라는 무결성은 지키면서, **"AI를 얼마나 잘 디렉팅했나"로 감독 실력이 드러난다.**
= 프롬프트 원툴 → 디렉팅 툴셋으로의 전환이 정확히 TK 통찰의 구현이며, compose 철학과
충돌하지 않는다.

## 발사 전 권고 (스코프 최소, 최대 효과)
1. **카탈로그 확장**(data-only): Hailuo 02 Pro(액션 품질) + Director(카메라 제어) + Sora 제거.
2. **카메라/모션 컨트롤 경량판**: `generation_jobs.user_params jsonb` + 워커 병합(~5줄) +
   **프리셋 칩(초보) + negative_prompt·camera 드롭다운(고수)**, 고급은 접힘.
3. **프롬프트 가이드/예시** 인라인.
→ 이 3개면 "프롬프트 원툴 → 디렉팅"이 발사 전 성립. 나머지(i2v 레퍼런스·multi_prompt
스토리보드·Motion Control)는 **발사 후**, i2v는 무결성 정책 결정 선행.
