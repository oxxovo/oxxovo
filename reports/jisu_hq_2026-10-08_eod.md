## 3. 오늘의 교훈 (성공만 적지 않는다)

1. **단위 시험 통과는 실행 통과가 아니다** (`exit 127`). 배포 검증 스크립트의 단위 시험 10개가 전부 통과했는데 `www`에 읽기 전용으로 실제 실행하니 검증은 성공했고 종료 코드만 `127`이었다. Windows에서 fetch 소켓이 닫히는 중 `process.exit()`를 부르면 libuv 단언으로 죽는다. 거짓 경고를 고치러 만든 검증이 또 거짓을 낸 구조였다. -> **스크립트·CLI는 실제로 한 번 실행해 종료 코드까지 본다. `process.exit` 대신 `process.exitCode`.** (메모리 `feedback_unit_pass_is_not_run_pass`)
2. **"한글이 없으면 한국어가 아니다"는 틀렸다** (H15). 화면이 `formatPT`를 우회해 `toLocaleString('ko-KR')`를 직접 불러도 **어떤 시험도 못 잡았다.** `ko-KR`은 한글이 아니라서 한글 스캔도 통과했고, 화면은 렌더 시험이 없고, 시각 시험은 `formatPT` 함수만 봤다. -> 한글 스캔은 한글만 잡는다. **로캘·서식은 화면 소스가 그 도우미만 쓴다는 소스 시험으로 따로 고정**(약한 시험이라는 한계를 인정하고 적는다).
3. **시험 환경이 실제와 같으면 훼손이 안 잡힌다** (PC가 PT). 작성자 PC가 `America/Los_Angeles`라서 "입력을 PT로 읽기"와 "브라우저 시간대로 읽기"가 같은 값을 내 훼손이 초록이 될 뻔했다. -> **자식 프로세스를 `TZ=UTC`로 강제**하고, 그 자식이 정말 UTC인지(`getHours()==7`) **대조군을 먼저** 확인한다. 이 Windows 환경에서는 `TZ=Asia/Seoul`이 무시된다(UTC만 먹는다) — 안 먹는 설정으로 짰으면 대조군 없는 PASS였다. 가드를 시험할 때는 **내 환경이 정답과 우연히 일치하지 않는지** 먼저 본다.
4. **alias 직후 틱은 옛 배포를 탈 수 있다.** 오늘 `c16b410`의 alias가 **20:25:00.868**에 붙었는데 **20:25:14 틱은 옛 배포(`dpl_FTmf39yb`)에서 돌았다**(alias 후 13초 경과). 같은 순간 `www`는 이미 새 SHA를 줬다(검증 `try 1` 통과). 즉 **`/api/version`이 새 SHA를 주는 것은 "크론이 새 코드를 탄다"의 증거가 아니다.** 지연의 최대치는 모른다(관측 1회 = 13초 이상). -> **⑩에서 실제로 걸린다** (아래 4절, 설계서 §5-8에도 적었다).
5. (어제부터) 훼손 시험이 초록이면 **가드가 아니라 시험을 의심한다.** 오늘 H15가 그 예였고, 반송 알림의 훼손 7번(러너 안쪽 `try`가 먼저 잡아 틱 `catch`에 안 닿음)도 같은 종류.

## 4. ★ ⑩ 때 걸리는 주의: 스위치를 열기 전에 틱이 새 배포에서 돈 것을 확인한다

⑩ 순서(설계서 §5-8)는 "코드 배포(스위치 닫힌 채) -> ... -> 스위치 하나만 열기 -> `[송출]`"이다. **배포 직후 스위치를 열면 바로 다음 틱이 옛 코드로 돌 수 있다**(오늘 13초 이상 관측). 옛 코드가 위험한 경우: 배포에 송출 경로 변경이 들어 있을 때(예: YouTube `title`/`type`이 없던 옛 코드면 4xx로 실패하거나 가시성을 못 정함).
- **규칙:** 배포 후 **로그에서 새 `deploymentId`로 찍힌 틱을 한 번 확인한 다음에만** 스위치를 연다.
  ```
  vercel logs --environment production --no-branch --since 15m --limit 300 --json -q "content-dispatch"
  ```
  각 줄의 `deploymentId`가 `/api/version`의 배포(`vercel api`로 `aliasAssigned`와 대조)와 같은지 본다. 시각으로 판정하고 줄 수로 판정하지 않는다(기본 100건 창).
- 양성 대조군: 같은 조회가 옛 배포 틱도 읽어낸다(오늘 `dpl_FTmf39yb`와 `dpl_E9NPNnTH`가 한 화면에 나왔다).

- 이 PC의 시간대는 `America/Los_Angeles`다. 시간대에 의존하는 시험은 자식 프로세스를 `TZ=UTC`로 돌리는 방식을 쓴다(`TZ=Asia/Seoul`은 무시된다).
- 훼손 시험 스크립트는 세션 임시 폴더에 있었고 레포에는 없다. 패턴: 파일을 읽어 정확한 문자열 한 곳을 바꾸고 테스트를 돌린 뒤 `finally`에서 원복, 마지막에 원복 후 초록 확인.

**작업 규칙(재확인)**
- SQL은 채팅 본문으로, 블록 하나에 쿼리 하나, 고유 태그 + `/* */`, 되돌리기는 별도. TK님이 Run, 지수는 Run 안 함. `ALTER TABLE`은 `RETURNING`을 못 쓰니 Success만 믿지 말고 `pg_attribute` 등으로 되읽는다. 컬럼·함수를 만들면 ACL도 `aclexplode`로 확인한다.
- **0건은 증거가 아니다. 대조군이 먼저다.** 훼손이 초록이면 시험을 의심한다. 스크립트는 실제로 실행해 종료 코드까지 본다. 내 환경이 정답과 우연히 같은지 의심한다.
- **여러 줄 수정은 편집 도구로.** 셸 치환·`node -e`·`String.replace($')` 금지(오늘은 한 줄 `sed` 치환과 파일에 쓴 스크립트만 썼고 diff로 확인했다).
- 사용자向 문안은 내 소관이 아니다(제니3). 운영자 내부 화면·알림은 용어만 확정표를 쓰고 문장은 제가 쓴다 — 단 문장 확인을 요청해 둔 상태.
- 안 맞으면 근거를 대고 반대할 것(TK 상시 지시). 실패·반례도 기록할 것.
- 오늘의 실수: 2건의 본부 메시지가 뉴스·제니2용으로 잘못 붙어 왔다(반송 메일 수신 / 뉴스 답변). 받는 쪽이 제가 아닌 것은 내용을 적용하지 않고 영향만 짚었다.
