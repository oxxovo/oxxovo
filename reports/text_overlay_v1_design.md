지수2 작성. 방침: 품질 우선. 드래프트 스튜디오 개방 8/5, 참가자 첫 편집기가 완성본이어야 함.

## 0. 핵심 결정 = 파리티 전략 (가장 어려운 문제)

TK님 지적대로 **브라우저 텍스트 렌더 ≠ ffmpeg drawtext**. 폰트 힌팅·줄바꿈·정렬·자간이
달라 프리뷰와 최종본이 어긋난다. 두 안:

- **(A) ffmpeg `drawtext`** — 새 의존성 없음. 그러나 레이아웃이 브라우저와 다름 → 파리티 약함,
  멀티라인/스트로크 제어 빈약. **비추천.**
- **(B) skia canvas 2D 래스터화 (추천)** — 워커에 `@napi-rs/canvas`(Skia 프리빌트 바이너리,
  Debian slim 호환) 추가. **브라우저 canvas 2D도 Skia, @napi-rs/canvas도 Skia → 동일 엔진.**
  같은 폰트 파일 + 같은 레이아웃 코드로 양쪽이 래스터화 → **글리프까지 시각적으로 동일.**

### 파리티 메커니즘 (LUT 선례를 그대로)
1. **동일 폰트 파일을 양 레포에 번들** (LUT가 `assets/luts` ↔ `public/luts`인 것과 동일 구조).
   앱: `public/fonts/*.woff2`(FontFace/preload) · 워커: 이미지에 `.ttf` + `assets/fonts/`.
2. **공유 결정론적 레이아웃 스펙**(양 레포 동일 구현): 글자크기 = `sizePct × 캔버스높이(px)`,
   줄바꿈 규칙, 고정 line-height, 정렬, 스트로크폭 = `k × fontsize`, 위치 = 정규화(xNorm,yNorm).
   - **프리뷰**: 오프스크린 canvas 2D(Chrome Skia)로 텍스트 래스터 → GL 캔버스 위에 **DOM
     `<canvas>` 오버레이**(비디오 표시영역에 정확히 겹침), playhead 시간 기준 fade 알파 적용.
     텍스트는 색보정 위에 올라감(최종본과 동일: grade 후 overlay).
   - **워커**: `@napi-rs/canvas`로 렌더 캔버스 해상도에 RGBA PNG 래스터 → ffmpeg
     `overlay=x:y:enable='between(t,start,end)'` + 알파 fade. (drawtext 미사용.)
3. **파리티 검증 스크립트** `scripts/text-parity.mjs`(효과의 `gl-engine-parity.mjs` 선례): 텍스트
   스펙 세트를 브라우저-canvas 경로와 워커-canvas 경로 양쪽에서 렌더 → PNG 픽셀/SSIM diff.
   **임계 통과해야 UI 노출**(효과와 동일 규율).

### 무결성 (Genesis)
- 참가자가 **이미지를 업로드하지 않는다.** 텍스트는 EDL의 **구조화 데이터**(문구/폰트/위치…).
  워커가 그 스펙으로 **서버에서 authoritative 래스터** → 클라 PNG 신뢰 안 함 → 임의 이미지
  삽입 치트 불가. "제품명·카피 텍스트"는 외부 소재가 아니라 창작자 카피 → Genesis 위배 아님.

## 1. 한글 폰트 (라이선스 클린)

- 워커엔 한글 폰트 없음 → **번들 필수.** 전부 **SIL OFL**(재배포·임베드 허용, 상업 이용 가능):
  - **Pretendard** (KO+Latin, UI 최적, 다중 웨이트) — 본문/카피 기본 추천
  - **Black Han Sans** 또는 **Noto Sans KR Black** — 굵은 타이틀/헤드라인용
  - (선택) **Noto Serif KR** — 세리프 필요 시
- v1은 **폰트 2종**(산세리프 1 + 굵은 디스플레이 1)로 시작 → 파리티 표면 최소화, 이후 확장.
- 동일 버전 파일을 양 레포에 커밋(woff2/ttf, OFL 재배포 조항 준수). LUT와 같은 관리.

## 2. 기능 범위 (v1)

- **텍스트 레이어 N개** (제품명 + 태그라인 + CTA를 서로 다른 시점에).
- 레이어당: **문구**(멀티라인) · **폰트**(허용 목록) · **크기**(캔버스 높이 % 슬라이더) ·
  **색**(팔레트+커스텀) · **정렬**(좌/중/우) · **위치**(9그리드 프리셋 + 자유 드래그, 정규화) ·
  **표시 구간**(startMs~endMs, 타임라인 기준) · **페이드 인/아웃(ms)**.
- **가독성**: 스트로크(외곽선) 또는 드롭섀도 토글 — 광고 텍스트가 영상 위에서 읽히려면 사실상
  필수(경쟁 도구 기본값). v1에 포함.
- 종횡비(9:16/16:9)와 무관하게 **정규화 좌표** → #3 종횡비 작업 후에도 위치 유효(디커플드).

## 3. EDL v2 + CryptoBind 배선

- `ComposeEdl`에 top-level `texts?: TextLayer[]` 추가(transitions처럼).
  ```
  TextLayer = { content, font, sizePct, color, strokeColor?, strokePct?, align,
                xNorm, yNorm, startMs, endMs, fadeInMs, fadeOutMs }
  ```
- `edlCanonicalStringV2`에 **`TX:` 섹션 append**(결정론적 정렬) → `computeEdlHash` → `v1sr`
  서명. **양 레포 바이트-미러 + GOLDEN KAT 갱신**([[project_final_score_design]] 계열의 KAT
  규율). 기존 효과-없는 EDL 해시는 불변(append-only).
- **모더레이션**: `createRender`/`submitRender` 서버에서 각 `texts[].content`를
  `moderateSubmission`(OpenAI omni, 텍스트 지원)로 스캔. 텍스트는 서명 EDL에 저장(감사).

## 4. ★모더레이션 — 솔직한 한계

- OpenAI omni-moderation: 욕설·성적·폭력·혐오 등 **불안전 콘텐츠는 잡음.** 그러나
  **타사 상표("Nike" 등)는 못 잡는다**(모더레이션 API 범위 밖).
- 상표는 자동 완전탐지 불가. 제안: **(a) 블록리스트**(주요 브랜드/금칙어, 운영이 관리) +
  **(b) 기존 admin 모더레이션 큐로 라우팅**(텍스트 포함 제출은 검토 대상). 완벽 자동탐지는
  약속 못 함 — 블록리스트+사람 검토가 현실적 최선. (TK 승인 필요.)

## 6. 8/5 일정 — 솔직한 조기 경보

- 오늘 7/22 → 8/5 = **14일**. 텍스트 v1(~8~10 d, 검증 포함)은 **텍스트만이면 8/5 안에 가능.**
- 그러나 **텍스트+음악(~6 d)+종횡비(~2~4 d)를 전부 검증완료로 8/5**는 ~16~20 dev-day →
  **14일 내 빠듯~초과.** 품질 우선 방침이면 셋 다 8/5은 위험.
- **조기 보고**(TK 지시대로): 텍스트는 8/5 목표 유지. **음악·종횡비는 8/5 직후로 밀릴 가능성
  높음.** 텍스트 v1 착지 후 더 정확히 재보고하겠음. TK님이 개방일 조정 또는 개방 시 필수범위
